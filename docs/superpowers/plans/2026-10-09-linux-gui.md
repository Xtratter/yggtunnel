# Linux client, plan 2: the Qt window

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `yggtunnel-gui`, a window that connects and disconnects through the running `yggtunneld`, shows state, errors and peers, imports a profile and shows the node log.

**Architecture:** A thin C++ layer (`DaemonClient` speaks the daemon's line-delimited JSON over a unix socket, `Controller` turns it into QML properties and actions) under a QML interface with Qt Quick Controls (Material style). The window knows nothing about the network; it only sends commands and renders what the daemon answers.

**Tech Stack:** C++20, Qt 6 (Core, Network, Quick, QuickControls2, Test), CMake + Ninja. No Qt Widgets, no extra libraries.

**Spec:** `docs/superpowers/specs/2026-10-09-linux-client-design.md` (section GUI). Plan 1 (`2026-10-09-linux-core-daemon.md`) built the daemon this window talks to.

## Global Constraints

- Neutral wording in all strings, code and docs: no mention of blocking, censorship, operators, throttling, «masking».
- No real IPs, ports, Ygg addresses, domains or keys in code, tests, screenshots or fixtures; examples only (`192.0.2.0/24`, `2001:db8::/32`, `200:db8::1`, `tls://192.0.2.1:1234`).
- Protocol is the daemon's: one JSON object per line; request `{"id":int,"cmd":string,"args":object?}`, response `{"id":int,"ok":bool,"error":string?,"data":any?}`, event `{"event":"state"|"log"|"peers","data":any?}`. Commands used: `status`, `up`, `down`, `panic`, `import` (`{"link":string}`), `log`, `version`.
- Socket path: `/run/yggtunnel.sock`, overridable with the environment variable `YGGTUNNEL_SOCKET`.
- `status` data: `{"state":"off|starting|connected|reconnecting|error","error":string?,"node":{…}?,"profile":{"name","serverYgg",…,"privateKey":"…abcd"}}`; `node` holds `running`, `address`, `uptime`, `peers[{uri,up,inbound,latencyMs,rx,tx,uptime,error?}]`, `tunnel{handshakeAgo,rx,tx}?`. The window never shows the private key, not even masked.
- UI languages: English and Russian (Qt translations `qsTr`, `.ts` files); default follows the system locale.
- The window never runs anything as root and never starts or stops the daemon.
- Docs bilingual (EN + RU), commits in English with author `Xtratter <1359019+Xtratter@users.noreply.github.com>`, trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Not in this plan (later plans): kill switch and split-routing cards, settings card (lanes, MTU), tray icon, PKGBUILD.
- Nothing is pushed or released without the user's explicit word.

## Review Focus

- Daemon not running / socket missing / permission denied: the window says so in words, offers no dead buttons, retries by itself, and recovers when the daemon appears. Task 2 and 3.
- Daemon restarts or the socket drops mid-session: pending calls fail cleanly, state returns to «unreachable», no crash. Task 2.
- A half-written or oversized line, or an event for an unknown kind: ignored, no crash. Task 1 and 2.
- `up` pressed twice quickly, or `up` while the daemon answers «already in progress»: the button is disabled while a call is in flight; the daemon's error text is shown, not swallowed. Task 3.
- Import of text without a link, a link that the daemon rejects, a file that is huge or binary: clear error, window state unchanged. Task 5.
- Long peer URIs and long error text: elided, never overflowing the card. Task 5.
- The private key must not appear anywhere in the UI or the log tab, even the masked form the daemon sends. Task 3.

### Task 2: `DaemonClient`

**Files:** Create `linux/gui/src/daemonclient.h/.cpp`, `linux/gui/tests/fakedaemon.h/.cpp` (a `QLocalServer` that speaks the protocol and can be scripted: reply, push events, drop the connection), `linux/gui/tests/tst_daemonclient.cpp`.

**Interfaces — Produces:**
```cpp
class DaemonClient : public QObject {
  Q_OBJECT
public:
  explicit DaemonClient(QString socketPath, QObject *parent = nullptr);
  bool isConnected() const;
  QString lastConnectError() const;                       // human text: "socket not found", "permission denied", …
  void call(const QString &cmd, const QJsonObject &args,  // reply or failure is delivered exactly once
            std::function<void(bool ok, const QString &error, const QJsonValue &data)> done);
  void start();                                           // connect now, then retry every 2 s while disconnected
signals:
  void connectedChanged(bool connected);
  void eventReceived(const QString &kind, const QJsonValue &data);
};
```
When the connection drops, every pending `done` is invoked with `ok=false, error="daemon connection lost"`.

### Task 3: `Controller`

**Files:** Create `linux/gui/src/controller.h/.cpp`, `linux/gui/tests/tst_controller.cpp`.

**Interfaces — Produces** (registered to QML as the context property `ctl`):
```cpp
class Controller : public QObject {
  Q_OBJECT
  Q_PROPERTY(bool daemonReachable READ ... NOTIFY changed)
  Q_PROPERTY(QString reachError READ ... NOTIFY changed)      // why the daemon cannot be reached
  Q_PROPERTY(QString state READ ... NOTIFY changed)           // "off"|"starting"|"connected"|"reconnecting"|"error"|"unreachable"
  Q_PROPERTY(QString lastError READ ... NOTIFY changed)       // daemon's last error or the failed command's error
  Q_PROPERTY(bool busy READ ... NOTIFY changed)               // a state-changing call is in flight
  Q_PROPERTY(bool hasProfile READ ... NOTIFY changed)
  Q_PROPERTY(QString profileName READ ... NOTIFY changed)
  Q_PROPERTY(QString serverAddress READ ... NOTIFY changed)
  Q_PROPERTY(QVariantList peers READ ... NOTIFY changed)      // [{uri, up, latencyMs, rx, tx, error}]
  Q_PROPERTY(QString nodeAddress READ ... NOTIFY changed)
  Q_PROPERTY(double handshakeAgo READ ... NOTIFY changed)     // seconds, -1 none
  Q_PROPERTY(QString nodeLog READ ... NOTIFY logChanged)
  Q_PROPERTY(QStringList history READ ... NOTIFY historyChanged) // "HH:mm:ss state[: error]" newest first, max 200
public:
  Controller(DaemonClient *client, QObject *parent = nullptr);
  Q_INVOKABLE void up();  Q_INVOKABLE void down();  Q_INVOKABLE void panic();
  Q_INVOKABLE void importLink(const QString &text);      // sends {"link": text}
  Q_INVOKABLE void importFile(const QUrl &file);         // refuses > 64 KiB, reads text, then importLink
  Q_INVOKABLE void refreshLog();
signals: void changed(); void logChanged(); void historyChanged(); void importFinished(bool ok, const QString &message);
};
```
Polls `status` every 2 s while connected (and once right after connecting); a `state` event triggers an immediate poll. The private key from `profile.privateKey` is dropped when parsing — it is never stored in a property or in `history`.

- [ ] **Step 1: Tests** with `FakeDaemon` scripted per case: `statusFillsProperties` (profile, peers, handshakeAgo); `stateEventUpdatesImmediately`; `unreachableWhenNoDaemon` (state `unreachable`, `reachError` non-empty, `up()` does nothing); `recoversWhenDaemonAppears`; `upSetsBusyAndClearsIt`; `secondUpWhileBusyIsIgnored` (exactly one `up` reaches the fake); `daemonErrorIsShown` (reply `{ok:false,error:"already in progress"}` → `lastError` equals it, `busy` false); `historyKeepsNewestFirstAndCaps200`; `privateKeyNeverExposed` (fake sends `privateKey:"…abcd"`; no property, history entry or `nodeLog` contains `abcd`); `importFileRefusesHugeFile`; `importLinkReportsDaemonError`; `panicCallsPanic`.
